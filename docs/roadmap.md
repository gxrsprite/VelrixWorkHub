## Web-first 业务优先级（当前排序）

当前交付面统一以完整 Web 端为准：业务页面、权限、菜单、查询、单据、审批、报表和跨模块链路先在 Web 端形成可独立验收的闭环。移动端、桌面端适配和微信小程序暂不进入近期开发，也不作为当前回归门槛；它们只在 Web 端业务和 API 稳定后再做。

业务排序按“先组织与流程底座，再 OA/PMS 高频闭环，再 CRM/ERP 深度经营，最后扩展终端”执行：

| 优先级 | Web 业务包 | 主要范围 | 进入条件 |
|---|---|---|---|
| P0 | 平台与 Workflow 业务底座 | 登录与权限、组织/人员范围、菜单、附件、待办、通知、通用审批动作和审计 | Workflow 引擎与模块 Application 边界稳定 |
| P0 | OA 人事与行政 | 组织与员工、招聘面试、入职、通讯录、离职、请假/出差/加班、借款/报销、资产/办公用品、车辆 | 平台底座和 Workflow 支撑当前用户隔离与审批 |
| P0 | PMS/PowerProject2 项目工作闭环 | 工作项、行动项、会议、项目日历、工时与审批、需求、缺陷、评审、发布和项目可见范围 | PMS 现有项目/WBS/成员/工时能力可复用 |

## LMS 许可证管理主线

## 执行顺序与完成定义

1. 先完成阶段 0 剩余规范和冒烟测试，保持 OA/CRM/ERP/PMS 现有主干可用；所有近期验收以完整 Web 端为准。
2. Workflow 只作为业务底座收口 CAS、事务、图运行时、失败回滚、待办/通知幂等和审计；表单运行时与 Canvas 设计器暂不作为下一交付目标。
3. OA 近期按 `OA-FLOW-01`～`OA-FLOW-04` 优先推进财务资金、采购申请、人事考勤/员工变动和车辆资源；与现有 OA-01～OA-08 合并验收，再推进 `OA-FLOW-05`～`OA-FLOW-08` 的资产、仓库、工程质量和 IT/安全，最后处理 `OA-FLOW-09`～`OA-FLOW-10` 的低频行政及非业务入口。
4. PMS 先按 `PMS-PMS-01`～`PMS-PMS-03` 完成项目立项/状态变更、工时矩阵和需求管理，再推进 `PMS-PMS-04`～`PMS-PMS-06` 的资源、组件和交付资产；PP2 工作项/会议/需求交付主链与上述对象合并建模，表单统一遵循两栏半宽/全宽字段基线。
5. 再推进 PMS 成本预算、CRM/ERP 深度单据与结算，并继续保持跨模块只经 Application 引用的边界；LMS 继续复用 CRM 主数据、OA 待办、Workflow、平台权限、附件和审计。
6. 制造、协作集成、统一查询、组织作业和 MCP 按 P1/P2 排期；移动端、桌面端适配和微信小程序统一放到 Web/API 稳定后的最后阶段。
7. 每项勾选前必须同时具备：领域规则、应用用例、页面/API、菜单权限、数据迁移/初始化和自动化测试；浏览器回归另行记录。
8. 不将旧系统的 WebForms 页面、SQL Server 专有 SQL、第三方 DLL、数据库表结构直接带入本项目。
